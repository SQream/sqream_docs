New Features
------------
► ``PIVOT ARRAY`` and ``PIVOT DISTINCT ARRAY`` accept a subquery in place of the list of values to pivot on. Please see :ref:`PIVOT ARRAY with a value query<pivot_array_value_query>`.

► New ``SHOW_STUCK_UNLINKS`` utility function lists deleted files whose removal from disk has failed. Please see :ref:`SHOW_STUCK_UNLINKS<show_stuck_unlinks>`.

► Dictionary chunk skipping also covers ``TEXT`` columns whose values vary in length, and numeric and date columns compressed with P4D compression. For a chunk that is not skipped, only the rows that might match the filter are copied to the GPU (SQ-23331, SQ-23334, SQ-23373). Please see :ref:`skipChunksUsingDictColumn<skip_chunks_using_dict_column>`.

► As of version 4.18.1, ``STOP_STATEMENT`` may also be run by the role that ran the statement, and no longer requires ``SUPERUSER``. A role that is neither a superuser nor the statement's owner is refused (SQ-23316). Please see :ref:`STOP_STATEMENT<stop_statement>`.

► As of version 4.18.1, an ``IN`` list longer than :ref:`inListJoinThreshold<in_list_join_threshold>` is compiled as an inner join, and now keeps chunk skipping on the listed column. The new :ref:`inListJoinMaxMetadataFilters<in_list_join_max_metadata_filters>` flag sets how many distinct values are kept as metadata filters, and :ref:`inListJoinMaxMetadataRanges<in_list_join_max_metadata_ranges>` how many ranges are kept past that limit. A dense list of ``INT`` or ``DATE`` values is compiled as the range it spans, controlled by the new :ref:`inListRangeMinValues<in_list_range_min_values>`, :ref:`inListRangeMaxMissingPercent<in_list_range_max_missing_percent>` and :ref:`inListRangeMissingMultiplier<in_list_range_missing_multiplier>` flags (SQ-23384). Please see :ref:`Compiling IN Lists<compiling_in_lists>`.

► As of version 4.18.1, the new :ref:`aggregateBelowRank<aggregate_below_rank>` flag places an aggregation below a rank window function, so that the window sorts groups rather than rows. It is off by default (SQ-23633).

Known Issues
------------
Using Grant operation on a specific UDF function fail.

:ref:`Percentile<percentile_disc>` is not supported for :ref:`Window Functions<window_functions>`

The Node.JS connector does not support ARRAY data types.

Deprecation
-------------------

► As of version 4.18.0, the ``enableLogDebug``, ``endLogMessage``, and ``useClientLog`` configuration flags are deprecated (SQ-23723). These flags are still accepted, but they have had no effect since earlier versions, and they will be removed in a future version. Remove them from your configuration files and scripts, because a ``SET`` statement that uses one of them will fail once it is removed. To control logging, use ``logClientLevel`` for the client log and :ref:`logDebugLevel<log_debug_level>` for the debug log. Please see :ref:`Logging<logging>`.

Upgrading to Version 4.18
-------------------------

Upgrading to this version requires an additional infrastructure, to support some of it's functionality. The requirements are listed below. In addition, it is required to perform a storage upgrade according to the listed process.


Additional packages
"""""""""""""""""""

   Please see additional installation requirements for In-process functions :ref:`in this page <in_process_python_functions>`

Storage upgrade
"""""""""""""""
► ``Running storage upgrade and metadata backup listed below are mandatory for this version``

1. Generate a back-up of the metadata by running the following command:

   .. code-block:: console

      select backup_metadata('out_path');
	  
   .. tip:: SQreamDB recommends storing the generated back-up locally in case needed.
   
   SQreamDB runs the Garbage Collector and creates a clean backup tarball package.
   
2. Shut down all SQreamDB services.

3. Copy the recently created back-up file.

4. Replace your current metadata with the metadata you stored in the back-up file.

5. Navigate to the new SQreamDB package bin folder.

6. Run the following command:

   .. code-block:: console

      ./upgrade_storage <levelDB path>
	


  .. note:: Upgrading from a major version to another major version requires you to follow the **Upgrade Storage** step. This is described in Step 7 of the `Upgrading SQreamDB Version <../installation_guides/upgrade_guide/version_upgrade.html>`_ procedure.
